# RC-03 — local model, synthetic lab and privacy boundary

Branch: ResidentChat/rc-03-local-model-synthetic-lab. Draft PR stacked on RC-02 Draft PR #2, which is stacked on RC-01 Draft PR #1. No automatic merge.

## Implemented
- Optional C# local Ollama /api/generate client restricted to direct IP loopback, no proxy, redirect or hosted cloud fallback.
- Strict response JSON schema: intent, category, urgency and requires_human. Unknown extra fields or invalid enums fail closed.
- C# safety floor: emergency, conflict and emergency urgency always require human review, regardless of model output.
- No model-issued commands; no model-triggered Telegram replies, ticket writes, file access, moderation or admin action.
- Input size, outer response size, nested response size and JSON depth bounded.
- Synthetic test handler used by tests/ResidentChat.SmokeTests; no real Ollama request in WSL.
- Optional separate manual-only CLI over five fabricated messages; only locally installed Ollama model allowed.
- Three-group Telegram test design in docs/TEST_GROUP_LAB.md. No groups created by program, no credentials configured.

## Test policy
Autonomous local WSL2 watcher, not GitHub Actions. Never use GitHub Actions to qualify this work. Results are immutable JSON in autotest-results branch at autotest-results/residentchat/pr-<PR_NUMBER>/<FULL_SHA>.json. Read only exact PR HEAD. No Relay Queue or tasks-v2.

Important: existing older PRs still contain legacy GitHub Actions definitions; RC-03 does NOT edit, enable or invoke them. All new commit messages have [skip ci] to suppress legacy workflows while WSL2 remains the only qualification source.

## Boundaries / limitations
The WSL2 test uses an in-memory fake response, so PASS is NOT evidence of Qwen model accuracy, speed, privacy isolation of the host or correct physical Telegram integration.
Local-model inference currently is not wired to Telegram ingress; webhook remains disabled by default.
Threat model, secrets, explicit customer authorization, durable idempotence, rate limits, incident routing, retention and egress firewall remain blockers before a Telegram pilot.


## RC-03 synthetic local-model scoring (2026-10-14)

The standalone `ResidentChat.LocalLab` opt-in CLI defaults to `qwen3:1.7b` and ONLY contacts the direct loopback Ollama server at `127.0.0.1:11434`. The local adapter requests non-streaming JSON with `think=false`, `temperature=0`, `num_predict=160`, `num_ctx=2048` to reduce CPU cost; these request invariants are verified with a fake handler in the mandatory WSL2 security gate.

Manual evaluation (NOT part of the WSL2 synthetic watcher):

```powershell
dotnet run -c Release --project tools/ResidentChat.LocalLab/ResidentChat.LocalLab.csproj -- --run --model qwen3:1.7b
```

This command processes six fixed fictional Ukrainian/Russian/English scenarios and outputs only case identifiers, expected and observed enum labels, human-escalation status, match count and latency. No transcript is emitted or persisted. The prompt-injection fixture has **no expected intent**: it is counted only for schema validity and cannot execute an action; it is not proof of injection robustness. A model-score failure indicates model quality or availability, not a failure of the WSL2 security gate.

RC-03 is still disconnected from Telegram. This step does not imply that the WSL2 runner can reach Ollama on the Windows host. Do not enable real-model calls in the mandatory synthetic WSL2 test pipeline.

## 2026-10-14 — independent review floor and real local acceptance

The private WSL2 infrastructure now runs TWO isolated checks per PR HEAD:
the original deterministic and networkless security gate, and a separate
opt-in local `qwen3:1.7b` evaluation via Windows Ollama loopback. The latter
publishes a distinct per-SHA JSON at `model-eval/pr-<PR>/<SHA>.json` in
the `autotest-results` branch. Neither check authorizes real Telegram traffic.

At `49ec375a50f7ebd360f5d878d4f0156d51fd676e`, the original security
gate passed and the real local evaluator reported LocalLab 6/6, but detailed
field comparison only 5/6: model-generated `Other/Routine` for a fictional
instruction-hijacking attempt had `requires_human=false` when the
expected escalation was true.

This update adds a **bounded, deterministic input-side C# review floor** for
clearly recognizable attempts to override model policy, impersonate system
instructions or disclose private data. It cannot be overridden by a false
`requires_human` from Qwen. Synthetic fake-transport regression tests include
English, Russian, Ukrainian, and benign FAQ controls. The separate real-model
CLI now treats its instruction-hijacking example as a full four-field match
rather than counting schema-valid alone.

**Limitations:** Heuristics are not comprehensive prompt-injection detection;
message quoting and adversarial spellings can cause false positives or misses.
Untrusted messages never gain tool authority, and human escalation is
a safety floor rather than authorization to send replies, moderate, or fetch data.
Six fabricated inputs are regression examples, **not production accuracy
estimates**. No autonomous actions, Telegram pilot, credentials or cloud LLM.
